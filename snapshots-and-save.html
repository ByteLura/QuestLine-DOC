Snapshots & Save

One snapshot for everything

tracker.CaptureState() returns one snapshot object holding the whole quest state: every quest's state, active nodes, objective counts, flags, stats, and achievement progress. The snapshot is built from list-based data transfer objects, so ToJson() / FromJson() round-trips through JsonUtility with no custom serializer.

Hand it to your save system

QuestLine Pro is deliberately not a save system. The snapshot is yours to store — file, cloud, platform — under your game's own autosave policy, slots and corruption handling. Two convenience stores ship for the common cases: a PlayerPrefs store and an in-memory store, behind the IQuestStateStore interface.

Restore re-fires nothing

tracker.RestoreState(snapshot) rebuilds the state exactly — and fires no completion events, no rewards, and no achievement unlocks while doing so. A StateRestored event fires once at the end so your UI can refresh. Loading a game never double-grants a reward or replays an unlock; this behaviour is covered by a dedicated acceptance test (restore-does-not-refire) on both Unity targets.

What a snapshot does not do

It does not version your content for you: if a quest definition changes shape between save and load, design your migration the way you would for any save data. It also does not replicate itself — networked games move the snapshot through their own transport.
