API Summary

The integration surface, in one page. The shipped ApiReference.md carries the full contract; this is the map.

Bootstrap

  • QuestLineRuntime — the MonoBehaviour bootstrap: builds a tracker over your catalog with your reward sink, exposes Tracker.
  • Or construct directly: new QuestTracker(catalog, rewardSink).

Tracker

AreaCalls
Progress AddProgress(targetId), AddProgress(kind, targetId)
World state SetFlag(id), AddStat(id, delta)
Lifecycle StartQuest(id), FailQuest(id, reason), RefreshAvailability()
Reads GetQuestState(id), GetObjectiveCount(questId, nodeId, objectiveId)
State CaptureState(), RestoreState(snapshot)
Events QuestAvailable / QuestStarted / QuestCompleted / QuestFailed, NodeCompleted, ObjectiveProgressed, StateRestored; achievements via tracker.Achievements (AchievementUnlocked, AchievementProgressed)

Your two implementations

  • Reward sink — receives each granted reward once, in order (kind, reference id, amount, custom key). Apply it to your inventory/economy; the tracker never owns the goods.
  • Platform transport — IPlatformTransport over your SDK for live sync (see Platform Adapters).

Definitions

Plain serializable data: QuestDefinition (nodes, unlock conditions), QuestNodeData (kind, objectives, conditions, rewards, routes, graph position), AchievementDefinition (linked quest or progress target, platform ids, hidden flag), all listed by a QuestCatalog. Titles resolve through QuestTextResolver — every player-facing string carries a key, so your localization pipeline can replace the resolver.
