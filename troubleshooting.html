Troubleshooting

First stops inside the product

  • Verify Install (home window, or Tools > ByteLura > QuestLine Pro > Verify Install) — six plain-language checks: runtime loaded, a quest driven to completion, a snapshot round-trip, a mock adapter unlock, the sample found, the documentation found.
  • Catalog Health (home window) — validation results for every quest in your catalog, errors first, each with an Open button that lands on the offending quest in the Tree Editor. A clean catalog reads “All quests pass validation.”

Common situations

A quest never becomes Available

Check its unlock conditions in the Inspector — a QuestCompleted condition names the quest that must finish first. Availability is re-evaluated on every tracker change; call RefreshAvailability() after bulk state changes.

An objective does not advance

The report's target id must match the objective's target id exactly, and the quest must be Active with that node active — a wait-at-the-gate branch upstream holds everything behind it until its conditions pass.

A reward fired twice — or not at all

Rewards fire once per node completion, through your sink. Restoring a snapshot never re-fires them; if your sink applies them twice, the duplication is in the sink.

The Tree Editor shows an empty canvas

The window opens on the quest you pick — use the toolbar picker, or open a quest from the home window or its Inspector.

Starter content is missing

Delete Assets/QuestLine Pro/ and click Create Starter Content again. The package keeps no other project state; the welcome toggle and catalog path live in EditorPrefs.

Adapters report unavailable

No transport is connected — that is the designed state until you register your own IPlatformTransport implementation (see Platform Adapters).
